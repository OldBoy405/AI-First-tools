1.3 修改的核心理念与预期目标

① 单一权威写入

「状态推进、账本修改、人工审批」全部收敛为 crctl 唯一写入通道（CAS + 审计日志），Skill 文档不再指导模型手工编辑 YAML，从提示词层面消除漂移。

对应不变量 1/2/6（ARCHITECTURE.md §5）

② 机械步骤代码化

把"回写 specs/delivery、CR-ID 分配、评审落盘"等确定性步骤固化为可执行脚本（writeback×3、cr-init、review-record），模型只做判断，不做机械操作。

对应 CR-2026-019/020/021

③ 漂移防线前置

lint-prompts 静态检查 prompt 与 crctl 契约一致性，pre-commit 与 CI 双重拦截（report → enforce 两阶段），让"状态机口径、命令形态"漂移在提交前被硬阻断。

对应 CR-2026-021 TASK-11/12/22

预期达成的目标（对照结果）
  • 漂移清零：CR-2026-021 TASK-22 已实现全量 lint 0 findings，pre-commit 切换 --mode enforce 硬阻断（FR-24 Phase 3）；
  • 状态死锁解除：REVIEW_STAGE_EXPECT 对齐 review-* SKILL（先写证据后 advance），code/requirement 评审态死锁解除；
  • 人工审批无旁路：四个审批节点仅限交互式 TTY 或 Ed25519 签名授权，非 TTY 调用一律拒绝；
  • 跨 IDE 可用：Qoder / Claude Code / Cursor / Codex / CI 五类适配器，脱离平台执行层时治理能力不缺失。
