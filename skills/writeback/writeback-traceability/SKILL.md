# Skill: writeback-traceability

**类型**: 回写期 Skill（writeback/ 组，第 4 节点）  
**调用时机**: feature-writeback pipeline 第 4 节点（倒数第二，cr-archive 之前）  
**前置要求**: CR status = `writing-back`，`specs/{spec_id}/PRD.md` 与 `SDD.md` 已回写

---

## 用途

聚合本次 CR 生命周期中产生的所有可追溯证据，生成 `specs/{spec_id}/traceability.yml`，建立需求→设计→任务→代码→CR 的完整追溯链。写入完成后保持 CR status=`writing-back`，由 feature-writeback pipeline 的下一节点 `cr-archive` 统一完成归档。

---

## 参数

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `cr_id` | string | ✅ | 目标 CR-ID |
| `spec_id` | string | ✅ | 关联 spec ID |
| `target_version` | string | ✅ | 目标版本号 |

---

## 执行步骤

### Step 1 — 前置校验

1. 读取 `change-requests/{cr_id}/cr.md`，确认 status=`writing-back`
2. 确认 `specs/{spec_id}/PRD.md`、`specs/{spec_id}/SDD.md` 均存在
3. 读取 `delivery/task/_index.yaml`，获取关联 cr_id 的任务 ID 列表

### Step 2 — 收集追溯证据

从以下来源收集数据：

| 证据类型 | 来源路径 |
|----------|----------|
| CR 基础信息 | `change-requests/{cr_id}/cr.md` |
| PRD 文档 | `specs/{spec_id}/PRD.md`（frontmatter: version, cr_ref） |
| SDD 文档 | `specs/{spec_id}/SDD.md`（frontmatter: version, cr_ref） |
| 技术评审记录 | `change-requests/{cr_id}/review-annotations/sdd.yml` |
| 需求评审记录 | `change-requests/{cr_id}/review-annotations/requirement.yml` |
| 代码评审记录 | `change-requests/{cr_id}/review-annotations/code.yml` |
| 测试报告 | `change-requests/{cr_id}/test-report.md` |
| 任务列表 | `delivery/task/_index.yaml`（filter: cr_ref={cr_id}） |
| 合并 commit | `change-requests/_backlog.yml`（字段: `merge-commits[]`，每项含 repo / trunk / sha / branch / source-sha / merged-at） |

### Step 3 — 生成 traceability.yml

写入 `specs/{spec_id}/traceability.yml`：

```yaml
# auto-generated by writeback-traceability — do not edit manually
spec_id: {spec_id}
version: {target_version}
generated_at: "{YYYY-MM-DDTHH:mm:ss+08:00}"
cr_ref: {cr_id}

owners:
  requirement:
    id: "{cr.md owners.requirement.id}"
    assigned_at: "{cr.md owners.requirement.assigned-at}"
  development:
    id: "{cr.md owners.development.id}"
    assigned_at: "{cr.md owners.development.assigned-at}"
  test:
    id: "{cr.md owners.test.id}"
    assigned_at: "{cr.md owners.test.assigned-at}"

prd:
  file: specs/{spec_id}/PRD.md
  reviewed_at: "{requirement-review timestamp}"
  approved_at: "{approval timestamp}"

sdd:
  file: specs/{spec_id}/SDD.md
  reviewed_at: "{sdd-review timestamp}"

tasks:
  - id: TASK-{ver}-{CR-NNN}-01
    file: delivery/task/TASK-{ver}-{CR-NNN}-01-{slug}.md
    status: done
  # ... 其余任务条目

code:
  repos:
    - repo: "{repo.id}"
      trunk: "{repo.trunk}"
      merge_commit: "{merge-commits[].sha}"
      source_branch: "{merge-commits[].branch}"
      source_sha: "{merge-commits[].source-sha}"
      merged_at: "{merge-commits[].merged-at}"

tests:
  report: change-requests/{cr_id}/test-report.md
  status: pass | block
  commands:
    lint: pass | fail | not-applicable
    test: pass | fail | not-applicable
    build: pass | fail | not-applicable
  uncovered_risks: []

reviews:
  requirement:
    file: change-requests/{cr_id}/review-annotations/requirement.yml
  sdd:
    file: change-requests/{cr_id}/review-annotations/sdd.yml
  code:
    file: change-requests/{cr_id}/review-annotations/code.yml
```

### Step 4 — 输出归档前置证据

在节点输出中写明：

- traceability.yml 路径
- 关联 TASK 数量
- merge commit SHA 是否齐全
- 未对齐项或 unknown 字段
- 下一节点必须是 `cr-archive`

### Step 5 — 输出摘要

```
✅ 追溯链生成完成，等待 cr-archive 归档
   spec_id         : {spec_id}
   traceability    : specs/{spec_id}/traceability.yml
   关联任务数      : {N} 个
   merge commits   : [{repo.id}={sha8}, ...]
   CR status       : writing-back
   下一步          : cr-archive
```

---

## 错误处理

| 错误 | 处理 |
|------|------|
| `review-annotations/` 下某文件不存在 | 在 traceability.yml 对应字段写 `null`，继续执行 |
| merge-commits[] 缺失或 repo SHA 不完整 | 停止执行，要求先修复 merge-feature-branch 输出；不得猜测或自动读取 trunk 最新提交 |
| CR status 非 `writing-back` | 停止执行，提示当前状态 |
