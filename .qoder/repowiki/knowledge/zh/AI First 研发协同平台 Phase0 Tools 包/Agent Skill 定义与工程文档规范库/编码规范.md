- 每个 Skill 以独立子目录 + `SKILL.md` 入口组织，frontmatter 中必填 name/description，可选 version/consumers/references，并在 description 首句标注类型（如「被动 skill」「需求期 Skill」）。
- Skill 正文采用「用途 → 触发条件 → 参数表 → 分步执行流程 → 落盘/提交 → 输出摘要 → 错误处理」固定章节顺序，参数表统一用 Markdown 表格列出名称/类型/必填/说明。
- 所有写入型 Skill 落盘路径遵循约定：PRD/SDD/TASK 等工程文档统一走 `engineering-docs` skill 生成的 `<type>-<name>.md` 文件名与 `_index.yaml` 索引更新流程，禁止手写 frontmatter。
- CR 相关 Skill 通过 `change-requests/{CR-ID}/cr.md` frontmatter 中的 status 字段驱动状态机，状态推进必须配合 `_backlog.yml` 同步更新，保持幂等。
- 时间戳统一使用北京时间 ISO 格式 `YYYY-MM-DDTHH:mm:ss+08:00`，ID 生成遵循 `conventions/naming.yaml` 与 `conventions/doc-chain.yaml` 链式编号规则。
- 审查类 Skill 的 checklist 项引用 `reviewer-panel.yaml` 中定义的 perspective 键名（如 REQ-01、SDD-03、CODE-05），并通过 severity=hard/soft 与 weight 参与聚合评分。
